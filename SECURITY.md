# Reporting security issues

Follow the existing [security model and reporting guidance](docs/security.md).
Report suspected vulnerabilities privately to the maintainer, @benjamin-small,
through an established private channel. Do not include exploit details, tokens,
customer data, or database contents in a public issue.

GitHub private vulnerability reporting was disabled when checked on October 1, 2026. If you do not already have a private contact channel, ask the maintainer
how to establish one without disclosing vulnerability details publicly.

Once a private channel is established, include the affected commit or version,
deployment configuration with secrets removed, reproduction steps, and impact.
This policy does not promise a response time or support window; coordinate
remediation and disclosure with the maintainer.
